# Скачиватель реестра лицензий Рособрнадзора

Скрипт получает данные с <https://islod.obrnadzor.gov.ru/rlic/> программой `curl`, сохраняет прогресс в SQLite и экспортирует CSV.

Полученные рабочие примеры запросов:

```powershell
curl.exe -sS -X POST --data "status=6&p=1" https://islod.obrnadzor.gov.ru/search
curl.exe -sS https://islod.obrnadzor.gov.ru/view/38300
curl.exe -sS https://islod.obrnadzor.gov.ru/branch/238805
```

По умолчанию скачиваются действующие лицензии: на 24.08.2026 это 136 271 лицензия. Полная обработка состоит из 13 628 страниц списка, одной карточки на лицензию и одной или нескольких страниц видов деятельности. Ограничение `16` новых запросов/с и не более `4` одновременных запросов рассчитано на завершение не более чем за 8 часов даже при большом числе филиалов. Временные ошибки, `429` и `5xx` повторяются; после остановки достаточно запустить ту же команду снова.

## План запросов

| Этап | Запрос `curl` | Число для действующих | Что извлекается |
|---|---|---:|---|
| Список | `POST /search`, тело `status=6&p=N` | 13 628 | ID, название, рег. номер, приказ, срок, статус |
| Карточки | `GET /view/{id}` | 136 271 | ИНН, КПП, полное/краткое название, адрес, дата изменений и ID веток |
| Виды деятельности | `GET /branch/{id}` | не менее 136 271 | Категории и уровни/подвиды деятельности |

Сервер игнорирует проверенные параметры увеличения страницы (`pageSize`, `limit`, `size`, `perPage`, `take`, `length`, `rows`), поэтому размер выдачи остаётся равным 10. Нижняя граница — 286 170 запросов, или 4 ч 58 мин при 16 запросах/с. В стратифицированном тесте карточка отвечала медианно за 0,185 с (95-й процентиль 0,234 с), типичный размер — 10,6 КБ; не более четырёх соединений достаточно, чтобы выдержать заданную частоту. Реальное число запросов веток становится известно после этапа карточек; встречаются крупные лицензии с десятками веток.

Для всех статусов найдено 306 588 лицензий на 30 659 страницах. Их теоретический минимум — 643 835 запросов (11 ч 11 мин при 16/с), ещё до учёта дополнительных веток, поэтому безопасно уложить этот режим в 8 часов нельзя. Скрипт выводит уточнённое число запросов и прогноз сразу после обработки карточек.

## Запуск

Требуются Python 3.10+ и `curl` 8+:

```powershell
python .\obrnadzor.py
```

Результат появится в `data/`:

- `licenses.sqlite3` — база и контрольные точки для возобновления;
- `licenses.csv` — все собранные поля;
- `active_inn_name.csv` — минимальная выгрузка `ИНН + Название` без дублей.

Быстрый тест на первых двух страницах без видов деятельности:

```powershell
python .\obrnadzor.py --output-dir sample --max-pages 2 --minimal
```

Повторный запуск с тем же каталогом продолжает незавершённую работу.

Во время скачивания консоль показывает прогресс каждого этапа, текущую скорость запросов и расчётное оставшееся время. Уже сохранённые данные сразу учитываются после повторного запуска:

```text
Details        [########------------] 40.00% 54,508/136,271 |  15.9 req/s | ETA 01:25:42
```

CSV можно пересобрать без сети:

```powershell
python .\obrnadzor.py --export-only
```

Все статусы поддерживаются отдельно, но не укладываются в восемь часов при безопасной скорости по умолчанию:

```powershell
python .\obrnadzor.py --scope all --output-dir data-all
```

Скорость и параллелизм регулируются явно, например `--rate 8 --parallel 3`. Если сайт отвечает `429` или `5xx`, не повышайте скорость: `curl` выполнит повторы, а следующий запуск продолжит с контрольной точки.
