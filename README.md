# Скачиватель реестра лицензий Рособрнадзора

Скрипт получает данные с <https://islod.obrnadzor.gov.ru/rlic/> программой `curl`, сохраняет прогресс в SQLite и экспортирует CSV.

Полученные рабочие примеры запросов:

```powershell
curl.exe -sS -X POST --data "status=6&p=1" https://islod.obrnadzor.gov.ru/search
curl.exe -sS https://islod.obrnadzor.gov.ru/view/38300
curl.exe -sS https://islod.obrnadzor.gov.ru/branch/238805
```

По умолчанию скачиваются действующие лицензии: на 24.08.2026 это 136 271 лицензия. Полная обработка состоит из 13 628 страниц списка, одной карточки на лицензию и одной или нескольких страниц видов деятельности. После наблюдавшейся временной блокировки примерно через 800–1000 запросов безопасная скорость по умолчанию снижена до `8` новых запросов/с. Один последовательный процесс `curl` получает пачку из 16 страниц с `--rate 8/s`, переиспользуя keep-alive соединение внутри пачки.

Скрипт использует постоянную сессию cookies и обычные заголовки HTML-клиента, не маскируясь под разные браузеры. При `Connection timeout` новые запросы останавливаются: в консоли каждую секунду обновляется длительность сбоя и число попыток, а контрольный запрос выполняется раз в 40 секунд. После успешного ответа скачивание продолжается автоматически.

## План запросов

| Этап | Запрос `curl` | Число для действующих | Что извлекается |
|---|---|---:|---|
| Список | `POST /search`, тело `status=6&p=N` | 13 628 | ID, название, рег. номер, приказ, срок, статус |
| Карточки | `GET /view/{id}` | 136 271 | ИНН, КПП, полное/краткое название, адрес, дата изменений и ID веток |
| Виды деятельности | `GET /branch/{id}` | не менее 136 271 | Категории и уровни/подвиды деятельности |

Сервер игнорирует проверенные параметры увеличения страницы (`pageSize`, `limit`, `size`, `perPage`, `take`, `length`, `rows`), поэтому размер выдачи остаётся равным 10. Нижняя граница — 286 170 запросов, или 9 ч 56 мин при 8 запросах/с без учёта пауз. Реальное число запросов веток становится известно после этапа карточек; встречаются крупные лицензии с десятками веток.

Для всех статусов найдено 306 588 лицензий на 30 659 страницах. Их теоретический минимум — 643 835 запросов (22 ч 21 мин при 8/с), ещё до учёта дополнительных веток. Скрипт выводит уточнённое число запросов и прогноз сразу после обработки карточек.

## Запуск

Требуются Python 3.10+ и `curl` 8+:

```powershell
python .\obrnadzor.py
```

Результат появится в `data/`:

- `licenses.sqlite3` — база и контрольные точки для возобновления;
- `licenses.csv` — все собранные поля;
- `active_inn_name.csv` — минимальная выгрузка `ИНН + Название` без дублей.

Быстрый тест на первых двух страницах без видов деятельности:

```powershell
python .\obrnadzor.py --output-dir sample --max-pages 2 --minimal
```

Повторный запуск с тем же каталогом продолжает незавершённую работу.

Во время скачивания консоль примерно раз в две секунды показывает прогресс каждого этапа, текущую скорость запросов и расчётное оставшееся время. Уже сохранённые данные сразу учитываются после повторного запуска:

```text
Started: 2026-08-24 22:30:00+03:00
Details        [########------------] 40.00% 54,508/136,271 |   7.9 req/s | ETA 02:52:30
```

При каждом переходе в режим ожидания отдельной строкой выводится локальное время начала сбоя: `Timeout started: 2026-08-24 22:45:12+03:00`.

CSV можно пересобрать без сети:

```powershell
python .\obrnadzor.py --export-only
```

Все статусы поддерживаются отдельно, но не укладываются в восемь часов при безопасной скорости по умолчанию:

```powershell
python .\obrnadzor.py --scope all --output-dir data-all
```

Скорость регулируется явно, например `--rate 4`. Размер одной последовательной сессии меняется через `--batch-size`, но его увеличение замедляет обновление progress-bar. Если ограничения повторяются, не повышайте скорость: следующий запуск продолжит с контрольной точки.
