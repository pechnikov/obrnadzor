# Скачиватель реестра лицензий Рособрнадзора

Скрипт получает данные с <https://islod.obrnadzor.gov.ru/rlic/> программой `curl`, сохраняет прогресс в SQLite и экспортирует CSV.

Полученные рабочие примеры запросов:

```powershell
curl.exe -sS -X POST --data "status=6&p=1" https://islod.obrnadzor.gov.ru/search
curl.exe -sS https://islod.obrnadzor.gov.ru/view/38300
curl.exe -sS https://islod.obrnadzor.gov.ru/branch/238805
```

По умолчанию скачиваются действующие лицензии: на 24.08.2026 это 136 271 лицензия. Полная обработка состоит из 13 628 страниц списка, одной карточки на лицензию и одной или нескольких страниц видов деятельности. После наблюдавшейся временной блокировки примерно через 800–1000 запросов безопасная скорость по умолчанию снижена до `8` новых запросов/с. Три последовательных worker-процесса `curl` делят общий лимит как `3/s + 3/s + 2/s`; каждый переиспользует одно keep-alive соединение внутри своей части пачки.

Каждый worker использует собственный постоянный cookie-jar и обычные заголовки HTML-клиента, не маскируясь под разные браузеры. При `Connection timeout` новые пачки останавливаются: в консоли каждую секунду обновляется длительность сбоя и число попыток, а один контрольный запрос выполняется раз в 40 секунд. После успешного ответа все worker-ы продолжают скачивание автоматически.

## План запросов

| Этап | Запрос `curl` | Число для действующих | Что извлекается |
|---|---|---:|---|
| Список | `POST /search`, тело `status=6&p=N` | 13 628 | ID, название, рег. номер, приказ, срок, статус |
| Карточки | `GET /view/{id}` | по числу уникальных ID | ИНН, КПП, полное/краткое название, адрес, дата изменений и ID веток |
| Виды деятельности | `GET /branch/{id}` | не менее 136 271 | Категории и уровни/подвиды деятельности |

Сервер игнорирует проверенные параметры увеличения страницы (`pageSize`, `limit`, `size`, `perPage`, `take`, `length`, `rows`), поэтому размер выдачи остаётся равным 10. Нижняя граница — 286 170 запросов, или 9 ч 56 мин при 8 запросах/с без учёта пауз. Реальное число запросов веток становится известно после этапа карточек; встречаются крупные лицензии с десятками веток.

Для всех статусов найдено 306 588 лицензий на 30 659 страницах. Их теоретический минимум — 643 835 запросов (22 ч 21 мин при 8/с), ещё до учёта дополнительных веток. Скрипт выводит уточнённое число запросов и прогноз сразу после обработки карточек.

## Запуск

Требуются Python 3.10+ и `curl` 8+:

```powershell
python .\obrnadzor.py
```

Результат появится в `data/`:

- `licenses.sqlite3` — база и контрольные точки для возобновления;
- `licenses.csv` — все собранные поля;
- `active_inn_name.csv` — минимальная выгрузка `ИНН + Название`, одна строка на лицензию.

Быстрый тест на первых двух страницах без видов деятельности:

```powershell
python .\obrnadzor.py --output-dir sample --max-pages 2 --minimal
```

Повторный запуск с тем же каталогом продолжает незавершённую работу.

Во время скачивания консоль примерно раз в две секунды показывает прогресс каждого этапа, текущую скорость запросов и расчётное оставшееся время. Уже сохранённые данные сразу учитываются после повторного запуска:

```text
Started: 2026-08-24 22:30:00+03:00
Details        [########------------] 40.00% 54,508/136,271 |   7.9 req/s | ETA 02:52:30
```

При каждом переходе в режим ожидания отдельной строкой выводится локальное время начала сбоя: `Timeout started: 2026-08-24 22:45:12+03:00`.

CSV можно пересобрать без сети:

```powershell
python .\obrnadzor.py --export-only
```

Все статусы поддерживаются отдельно, но не укладываются в восемь часов при безопасной скорости по умолчанию:

```powershell
python .\obrnadzor.py --scope all --output-dir data-all
```

Скорость регулируется явно, например `--rate 4`. Размер одной последовательной сессии меняется через `--batch-size`, но его увеличение замедляет обновление progress-bar. Если ограничения повторяются, не повышайте скорость: следующий запуск продолжит с контрольной точки.

## Контроль полноты по субъектам РФ

Отдельный контрольный проход можно запустить одновременно с основным сбором:

```powershell
python .\control_pass.py
```

Он использует собственную базу `control/control.sqlite3`, один последовательный worker и не более одного дополнительного запроса в секунду. Основная база открывается только для итогового сравнения. Повторный запуск продолжает контрольный проход с сохранённых страниц.

Для каждой строки сохраняется связь `субъект → страница → позиция → ID`. После полного прохода создаются:

- `control/missing_from_main.csv` — ID регионального прохода, отсутствующие в основной базе;
- `control/main_only.csv` — ID основной базы, не найденные в региональном проходе;
- `control/regional_duplicates.csv` — повторные ID с номерами страниц;
- `control/union.csv` — объединение основной и региональной выборок с источником записи и ИНН;
- `control/union_missing_inn.csv` — очередь карточек, для которых ИНН ещё не получен;
- `control/union_summary.xlsx` — компактная сводка по объединению;
- `control/summary.csv` — итоговые количества.

Чтобы дополнить объединение ИНН из карточек, запустите:

```powershell
python .\fill_inn.py
```

Загрузчик использует три последовательных curl-worker и общий лимит 8 запросов в секунду.
Новые региональные лицензии и скачанные карточки сохраняются непосредственно в основной базе
`data/licenses.sqlite3`. Если осталась база прежней версии `control/inn.sqlite3`, при запуске она
сначала импортируется. После окончания обновляются штатные `data/licenses.csv`,
`data/active_inn_name.csv`, а также контрольные `union.csv` и `union_missing_inn.csv`.
